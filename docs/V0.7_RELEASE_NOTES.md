# Aquadecomp v0.7 Release Notes

**Release Date**: November 2, 2026  
**Focus**: Distributed Redis Caching for Multi-Machine Deployments

## What's New in v0.7

### Distributed Redis Cache Integration

v0.7 introduces **three-layer hybrid caching** combining local memory, persistent disk, and distributed Redis:

```
L1: In-Memory Cache (0.1ms)    — per-process, fastest
L2: Persistent Disk (2–5ms)    — per-machine, survives restart
L3: Distributed Redis (10–30ms) — cluster-wide, multi-machine sharing
```

### New Components

#### 1. DistributedRedisCache (285 lines)
- Redis connection pool management (JedisPool)
- TTL-based automatic expiration (default 24 hours)
- Thread-safe get/put operations
- Graceful fallback on connection failure
- Cache invalidation and monitoring

#### 2. HybridCacheManager (380 lines)
- Orchestrates multi-layer cache access
- 5 configurable strategies:
  - `LOCAL_ONLY` (memory only, like v0.5)
  - `LOCAL_PERSISTENT` (memory + disk, like v0.6)
  - `LOCAL_REDIS` (memory + Redis)
  - `LOCAL_PERSISTENT_REDIS` (three-layer hybrid, recommended)
  - `REDIS_ONLY` (stateless nodes)
- Unified statistics collection
- Transparent fallback if Redis unavailable

#### 3. ParallelRecoveryPipeline Enhancements
- New constructor overload supporting Redis configuration
- Transparent hybrid cache integration
- Enhanced stats methods for cache monitoring
- Backward-compatible with v0.6 code

## Backward Compatibility

✅ **100% backward compatible with v0.6**

```java
// v0.6 code works unchanged
ParallelRecoveryPipeline pipeline = new ParallelRecoveryPipeline(8, true, cacheDir);

// v0.7 adds Redis with optional constructor parameter
ParallelRecoveryPipeline pipeline = new ParallelRecoveryPipeline(
    8, true, cacheDir, "redis.local", 6379,
    HybridCacheManager.CacheStrategy.LOCAL_PERSISTENT_REDIS
);
```

If Redis is unavailable, system silently falls back to v0.6 behavior (local + persistent).

## Migration Guide

### From v0.6 to v0.7

#### Option 1: Keep v0.6 Behavior (No Changes)
```java
ParallelRecoveryPipeline pipeline = new ParallelRecoveryPipeline(8, true, cacheDir);
// Uses LOCAL_PERSISTENT (v0.6 default)
```

#### Option 2: Add Redis (Recommended for Teams)
```java
ParallelRecoveryPipeline pipeline = new ParallelRecoveryPipeline(
    8, true, cacheDir,
    "redis.corp.internal", 6379,
    HybridCacheManager.CacheStrategy.LOCAL_PERSISTENT_REDIS
);
```

#### Option 3: Stateless Nodes (Kubernetes/Cloud)
```java
HybridCacheManager hybrid = new HybridCacheManager(
    HybridCacheManager.CacheStrategy.REDIS_ONLY,
    null, "redis.cloud.local", 6379
);
// No local cache, all nodes share Redis
```

## Configuration for Production

### Docker Compose Quick Start
```yaml
version: '3'
services:
  redis:
    image: redis:7-alpine
    ports:
      - "6379:6379"
    command: redis-server --maxmemory 1gb --maxmemory-policy allkeys-lru

  aquadecomp:
    image: aquadecomp:v0.7
    environment:
      REDIS_HOST: redis
      REDIS_PORT: 6379
      CACHE_STRATEGY: LOCAL_PERSISTENT_REDIS
```

## Known Issues & Limitations

### Known Limitations
- Single Redis node (no cluster failover yet)
- Manual cache invalidation required on library updates
- No predictive cache warm-up

### Workarounds
1. **Redis Unavailability**: System automatically falls back to v0.6 behavior
2. **Cache Invalidation**: Call `hybridCache.invalidateAll()` when dependencies change
3. **Cache Warm-up**: Pre-populate Redis by running first decompilation on each library version

### Redis Authentication
For production, enable Redis AUTH:
```redis
requirepass your-secure-password
```

Then configure:
```java
DistributedRedisCache redis = new DistributedRedisCache("redis.local", 6379);
```

### Network Security
- Deploy Redis behind VPN or private network
- Use TLS with Redis 6+
- Restrict port access to decompiler nodes only
